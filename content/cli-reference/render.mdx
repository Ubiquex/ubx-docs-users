---
title: "ubx render"
description: "Generate blueprint override statements from real drift, in the calling stack's own SDK language."
---

`ubx render` generates override statements directly from live drift,
mechanically, with zero AI. For one drifted resource (`--from-drift`)
or every drifted resource in a stack (`--sync-overrides`), it writes the
override that would pin the resource's current, drifted values, in the
calling stack's own SDK language. It never writes to the ledger.

It used to also project a stack's current state as a D2 diagram or,
with `--md`, a markdown document. Those outputs, and `--md`, `--out`
and `--check` with them, are gone: with an agent authoring changes and
the ledger recording them, nobody was reading a committed projection.
[`ubx status`](/cli-reference/status) and [`ubx why`](/cli-reference/why)
answer what exists and how it got that way.

## Usage

```bash
ubx render [flags]
```

## Examples

Generating override statements from real drift:

```bash
ubx render --stack payments --sync-overrides
```

```bash
sdk.Override("payments.aws_sqs_queue.pipeline-events", map[string]any{
	"message_retention_seconds": 1209600,
})
```

One drifted resource only:

```bash
ubx render --stack payments --from-drift payments.aws_sqs_queue.pipeline-events
```

## Flags

<ResponseField name="--stack" type="string">
  Which stack. Required: override generation always covers exactly one stack.
</ResponseField>

<ResponseField name="--from-drift" type="string">
  Generate a single override statement for one drifted resource's address. Mutually exclusive with `--sync-overrides`.
</ResponseField>

<ResponseField name="--sync-overrides">
  Walk the whole stack's drift and generate an override statement for every drifted resource.
</ResponseField>

<ResponseField name="--source / --provider-version / --provider" type="string">
  Provider selection. `--provider` and `--source` are mutually exclusive; `--source` requires `--provider-version`.
</ResponseField>

<ResponseField name="--provider-config" type="string" default="{}">
  JSON object configuring the provider (default `{}`).
</ResponseField>

<ResponseField name="--ledger-dir" type="string" default=".">
  Root directory containing `ledger/` and `.ubx/` (default `.`).
</ResponseField>

<ResponseField name="--timeout" type="string" default="1m0s">
  Overall timeout for the drift scan (default `1m0s`).
</ResponseField>

## Notes

One of `--from-drift` or `--sync-overrides` is required. Both are
entirely mechanical: they read the same real drift comparison
`ubx status --drift` already computes and template it into the calling
stack's own SDK language, auto-detected, never guessed.
